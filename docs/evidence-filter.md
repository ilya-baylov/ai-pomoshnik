# Один хороший источник не подтверждает остальные

[На главную](../README.md)

## Проблема

При подготовке ответа по данным компании проверялся лучший результат поиска. Если он проходил порог, в контекст могли попасть и остальные фрагменты с низкой оценкой.

Например, при пороге 0,55 поиск вернул инструкцию по согласованию с оценкой 0,9 и посторонний документ с оценкой 0,1. Второй фрагмент тоже передавался модели. Это увеличивало объём лишнего контекста и создавало риск использования неподходящих сведений.

## Изменение

Теперь порог применяется к каждому фрагменту перед сборкой ответа. В приведённом случае модель получает только инструкцию. В списке источников и журнале использованных фрагментов также остаётся только она.

Если ни один фрагмент не прошёл порог, запрос внутренних сведений завершается сообщением о недостатке данных без обращения к модели. Общие рабочие советы обрабатываются отдельно.

## Проверка

В `tests/test_answer_evidence.py` есть воспроизводимый случай с двумя фрагментами: до исправления проверка находила посторонний текст в контексте модели, после исправления — нет.

Там же проверяются отказ при отсутствии источников, слабое совпадение, выдача цитаты для выбранного раздела и отказ от неподтверждённой суммы после неудачной попытки исправить ответ.

```bash
python -m pytest tests/test_answer_evidence.py -q
```

Тесты подменяют модель. Они подтверждают работу отбора источников и защитных веток кода, но не измеряют точность ответов реальной LLM и не доказывают отсутствие всех галлюцинаций.
